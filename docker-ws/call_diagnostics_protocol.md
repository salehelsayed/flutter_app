Call diagnostics bridge and relay contract (schema 1)

The app sends bridge action `call_diagnostics_v1`; native dispatch calls `callDiagnosticsV1(paramsJSON)` and Go exports `CallDiagnosticsV1(paramsJSON string) string`. All replies use the existing bridge `{ok:true,data:{...}}` envelope. No diagnostic operation changes call authority.

- `capabilities`: data `{supported:true,version:2}`.
- `configure`: inputs `enabled`, `pushTrace` (default false), and required positive `consentEpoch`. All upload/clear operations also carry the current epoch; the Node injects it into wrapped business requests. Epoch must increase whenever consent changes; the relay persists the highest authenticated-device epoch, rejects older or equal-conflicting settings, and accepts equal-identical refreshes. Data `{supported:true,enabled:bool}`; failure includes a fixed `reason`. Consent defaults off.
- `upload`: inputs `events` plus optional `summaries`, combined maximum64 records, each validated against `tool/call_diagnostics/schema_v1.json`. Data `{supported:true,acceptedEventIds:[],rejectedEventIds:[]}`. Only accepted IDs have been durably persisted. Invalid schema/foreign-trace uploads and permanent ordinary trace-cap refusals are terminal rejects; the latter use reason `quota_exceeded`. Disk/global-quota/owner-quota/stale-consent failures leave IDs unacknowledged for retry. Always process both ID lists even when the response also contains a reason. Client source `relay` and role `server` are rejected. Endpoint terminal summaries and each authenticated endpoint's first verified-media record have separate bounded slots after the ordinary event quota. A private256-ID refusal ledger deduplicates permanent discards; saturation reports a lower bound rather than repeatedly counting retry attempts.
- `resolve`: input `callHandle` (private command input, never diagnostic output). Data `{supported:true,resolved:bool,traceId?:UUID}`. Only the authenticated participant of a successfully stored call can resolve a trace.
- `bind`: inputs `callHandle`, `traceId`; data `{supported:true,bound:bool}`. This confirms a previously proven participant binding; it cannot enroll a claimed peer. Authenticated successful mailbox Store establishes caller/callee membership. Preflight upload can create an owner-only trace without any handle.
- `clear`: requires a higher epoch, erases associated records/bindings and preserves the current enabled flag. Data `{supported:true,enabled:bool}`. Same-epoch identical configure is then idempotent; old-epoch uploads and wrapped diagnostic requests are ignored. Configure(false) purges records and retains the disabled epoch tombstone.
- Old or storage-disabled relays return `{supported:false}`. Network failure uses the existing fixed bridge error envelope; callers must retain their local spool and keep call behavior independent.

Existing Call*V1 JSON accepts optional `diagnostics:{traceId?,requestId?,operationId?,parentOperationId?,cause?}`. At least traceId or operationId is required; all identifiers are canonical UUIDv4 values. Operation-only contexts describe authority changes and do not create a call trace. Malformed diagnostics are stripped before the existing strict call decoder. No diagnostic property participates in a canonical signature.

Separate configure/capabilities operations negotiate relay support. Business calls never block on a capability probe. A known configured relay receives `{action:"call_diagnostics_v2",op:"request",consentEpoch:<current epoch>,request:<unchanged v1 JSON>,diagnostics:<context>}`; its reply is the unchanged v1 response. Absent support sends v1 bytes. An explicit old-relay `Unknown action: call_diagnostics_v2` permits one v1 fallback; ambiguous transport/reply failures do not trigger an extra diagnostic-specific retry.

TURN uses new native `turnCredentialsWithDiagnosticsV1(paramsJSON)` / Go `TurnCredentialsWithDiagnosticsV1(paramsJSON string) string`. Its input is `{diagnostics:{...}}`; the old no-argument API remains unchanged. Diagnostics preserve the overall credential deadline. Server events distinguish request/mint/write; coturn allocation outcomes remain aggregate and are not represented as per-trace proof.

A consenting recipient must separately configure `enabled:true,pushTrace:true`. Only then an authorized wake includes outer `diagnostics:{schemaVersion:1,traceId:UUID}`. APNs uses an object; FCM data uses its compact JSON string. Native strips this metadata before the strict existing v1 authority decoder; malformed metadata does not reject valid legacy authority. Base payload remains bounded256bytes; addon≤128bytes.

Relay deployment sets `CALL_DIAGNOSTICS_DIR` to a dedicated writable protected directory. Without it, diagnostics advertise unsupported. Files are0700-directory/0600-data, independent of mailbox Redis; retention14days by server receipt, global64MiB, per-owner5MiB. A joined trace allows768 ordinary events/192KiB event payload: two independently bounded256-event/64KiB endpoint spools plus one equally bounded relay contribution. Reserved first-media/terminal evidence, wrappers and the discard ledger fit within a320KiB serialized-record ceiling. Client local limits remain unchanged. Raw handles, tokens, addresses, identities, messages and envelopes are excluded from event output. Private authorization maps use domain-separated input digests solely for lookup; these never appear in exported events. Queue/storage failure is fail-open for calls and counted using fixed labels.

Historical `Dropped` values from the earlier relay counted refusal attempts, including retries. Startup migrates them to `legacyDropAttempts`; the operator reports these separately from distinct modern discards and marks their unique-loss count unknown. Neither migration nor export claims those historical attempts were unique lost events. The private discard ledger follows normal record expiry and consent erasure, and is never exported.

Read-only operator commands (run as the service user or an authorized operator):

```sh
python3 docker-ws/call_diagnostics.py --dir /var/lib/mknoon/call-diagnostics --hours 24
python3 docker-ws/call_diagnostics.py --dir /var/lib/mknoon/call-diagnostics --trace <UUIDv4> --hours 336
```

The overview distinguishes any-endpoint reported media from both caller+callee reported media, caller/callee terminal completeness, legacy traces, and unknown endpoint roles. It never calls ACK or TURN mint an audio success. `relay_call_diagnostics_storage_ready` and fixed-cardinality `relay_call_diagnostics_events_total` expose unavailable storage and bounded queue/sink loss. No trace identifier is a metric label.

Exact bridge/relay context fixtures are in `tool/call_diagnostics/wire_fixtures_v1.json`. Outer metadata uses `cause`; persisted event records use `reason`. Both Go decoders and the Dart runtime test this shared fixture.

The operator computes preflight rejection, classified technical setup failure, answered-without-media, drops after media, registration withdrawals by origin, provider/credential failures, telemetry loss and cleanup failure. Every rate exposes a numerator/denominator and minimum5 observations; normal declines/cancels/busy/no-answer are outside the technical denominator. Lookup includes the first received failed phase, missing stage reports and a bounded parent-operation join into retained authority/runtime records. Delayed receipt order is not asserted as device causal order.

Direct-only limitation: calls race direct and mailbox legs. Direct acceptance can succeed while mailbox Store fails. Shared relay participant binding requires successful Store, so direct-only/no-custody endpoints can remain separate or provisional. The operator exposes missing endpoint evidence and does not infer a complete joined trace.

Rollback/runbook requirement: explicitly disable diagnostics and wait for successful relay opt-out before installing an older native app. Desired push-trace consent survives14days, but effective parser capability is process-local. A successful authenticated legacy call-token registration suppresses the additive push metadata without altering desired consent/high-water epoch. A fresh same-epoch configure from the current app restores it; delayed earlier configure cannot undo a newer observed legacy registration. Relay restart also requires fresh configure before adding push metadata. The relay cannot observe a binary rollback before any post-rollback request/registration, so arbitrary rollback before opt-out is not claimed safe. Never-opted-in old peers keep the exact legacy payload.
