What this changes in code

  • Tap target — the private-media-card-visual tile gets wrapped in an InkWell; PrivateMediaVisualCard takes an onTap and the action: slot goes unused for this state.
  • Gone — the private-media-open button, the Protected photo title (private_media_card_title_protected_photo), and the You can view it again. lead-in.
  • New string — "{name} doesn't allow saving or sharing." replaces private_media_protected_body_received. Trailing period kept to match the rest of the private-media copy — say the word and I'll drop it.
  • Spinner — while opening, the tile dims and the lock swaps to a spinner in place (the button used to carry that state).
  • Accessibility — the removed title still lives on as the Semantics label, so screen readers keep announcing "Protected photo".

Two things worth flagging

  • The tile can't become a real blurred thumbnail. That gradient is deliberate — direct_private_media_viewer.dart:455 guarantees "private pixels never enter this widget through a path, provider, attachment, or byte payload." A blurred preview of the actual photo would mean decrypting it before the recipient opens it, which breaks the protected-media contract. The mockup keeps the gradient+lock.
  • Same card, four other states. PrivateMediaVisualCard also renders view-once, disappearing, the sender-side bubble, and the open-failure card — plus the group copy at group_conversation_screen.dart:1088. Tell me whether tap-the-tile applies to all of them or to protected-only, and I'll scope it that way.
