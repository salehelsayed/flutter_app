6 · Around the app Leaving the call screen keeps the call alive; the green bar returns to it. A second incoming call shows a banner — accepting it would end the current call, so the banner warns first (v1: auto-busy).

Edge cases the UI must answer

  • No answer (45 s): caller sees "No answer"; callee gets a missed-call row + a normal notification.
  • Callee already on a call: automatic "Busy" — no ring on the callee's side (v1).
  • Declined: caller sees "Call declined"; a call row is written on both sides.
  • Network drops mid-call: "Reconnecting…" overlay up to 30 s, then the call ends with "Connection lost".
  • Permission missing: mic (and camera for video) is requested before dialing; no permission → no call.
  • Stale invite: an invite older than 45 s (delayed push, relay replay) never rings — it becomes a missed call.

Privacy story (shown in Settings / first call)

  • Calls are end-to-end encrypted (WebRTC DTLS-SRTP). Keys are exchanged over the already-encrypted mknoon message lane.
  • Audio and video flow directly between the two phones whenever the network allows.
  • If a direct path is impossible, the mknoun relay forwards the encrypted stream — it cannot read or hear anything.
  • No call content is ever stored. Only the call rows (time, duration, missed) exist, on the two devices.

Media: WebRTC (Opus audio, VP8/H.264 video) via flutter_webrtc · Signaling: existing encrypted 1:1 message lane (offer / answer / ICE / end) · Wake-up when killed: APNs VoIP push + CallKit on iOS, high-priority FCM data push + full-screen notification on Android · NAT fallback: coturn (STUN/TURN) on mknoun.xyz.
