Plain-English gloss of project terms used below:
- **wake token** = an opaque per-contact "doorbell key"; the relay (server) only rings a recipient's phone if the sender presents a key the recipient issued ("only contacts can wake you").
- **v2 contact_request** = the *encrypted + signed* friend-request envelope (the only per-contact-private, authenticated 1:1 channel). **v1** = the older *plaintext* one.
- **the attach funnel** = `P2PServiceImpl.storeInInboxDetailed` — the single place every "leave a message in the recipient's relay inbox" call passes through.
- **enforcement / the gate** = the relay's `wakeTokenGateEnforced` switch; today OFF ("fail-open" = every push wakes). Turning it ON is what makes the doorbell rule real.
- **backfill** = re-reaching existing contacts (re-uses the ML-KEM re-announce drain) so they get your token too, not just new contacts.
- **Move** = the account-migration feature (not touched here; noted only for context).

## §A — Correctness defects (the plan would malfunction / mislead as written)
