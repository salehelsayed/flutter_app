## Problem And Evidence

- `defaultDirectMediaLaneQualifier` currently returns `eligible`, so Save/Files/Share and library batch egress do not consume the durable private parent state.

- direct Shared Media SQL filters live/visible direct parents but does not exclude non-ordinary, unsupported, terminal, or corrupt private parents.

- viewer/bubble capabilities are presentation snapshots. They can hide actions, but they cannot be dispatch authority.

The durable `ConversationMessage.privateMediaPolicy`, `privateMediaState`, `hiddenAt`, lifecycle timestamps, and current direct attachment identity are already the authority. This session adds no schema and makes no native or PiP implementation claim.

## Scope Contract And Guard

### Central current-parent decision

Add one direct-chat application policy, for example `DirectPrivateMediaActionEligibility`, that is computed from the freshly loaded current `ConversationMessage` plus the exact current direct attachment where an attachment is required. It must expose typed decisions consumed by all Session-04 surfaces rather than caller booleans or path/MIME snapshots.

The decision must distinguish at least:

- ordinary/live content, which preserves current behavior;
- available `protected`, `view_once`, or `disappearing` content;
- terminal `consumed` or `expired` content;
- unsupported, corrupt, hidden, deleted, missing-parent, wrong-owner, and stale-identity content.

For every private or unsupported mode, deny Photos/Files Save, external Share, internal Forward, bookmark, Shared Media presence/batch egress, and Picture in Picture. For private content, the only user-level action capabilities are generic Reply, privacy-minimized Info, and Delete-for-me. Available private content may retain the already-accepted in-app open/manual-download path; terminal, unsupported, hidden, deleted, or corrupt content may not expose bytes or re-download. Reply output is the generic localized meaning `Private media`, never caption, thumbnail, path, MIME-derived copy, duration details, or keys. Info may expose only typed truthful mode/expiry/lifecycle facts needed by Session 05, never a path, key, nonce, caption, thumbnail, or export handle.

Publish a typed `canEnterPictureInPicture` decision. It is `false` for every private, unsupported, terminal, hidden, deleted, missing, corrupt, or unresolved state. Ordinary media preserves its existing eligibility input; Plan 243 remains the owner of actual PiP implementation and platform proof.

### Dispatch-time authority

- Replace the ordinary-only default direct-lane qualifier in `received_media_action_controller.dart` with the central current-parent decision. Single and batch Save/Share must reload current parent plus exact direct attachment immediately before egress; a stale viewer/library snapshot never authorizes the native service.
- Make `BuildReceivedMediaForward` re-read the current parent by stable message identity before reading files or creating any `ShareIntent`. Every private/unsupported/terminal state returns a typed denial with zero picker, token, file, or transport side effects. Ordinary Forward behavior and provenance remain unchanged.
- Keep UI capability filtering for truthful presentation, but route bubble, conversation viewer, and Shared Media viewer adapters through the same typed decision. Direct-call seams remain authoritative even if a UI caller bypasses or races rendering.
- Explicit download must consume the same parent decision. Available private media retains Session-02/03 manual app-local download; terminal/unsupported/hidden/deleted/corrupt parents fail before bridge/file commit. Do not weaken Session-03's atomic final-commit CAS.

### Shared Media and bookmark authority

- Add direct-parent SQL exclusion to `dbLoadMediaLibraryPage`: a direct row enters Shared Media only when its current parent is the canonical ordinary/non-private lifecycle state. Non-ordinary, unsupported, terminal, corrupt, or hidden/deleted parents are excluded before pagination. Group scope and same-ID group siblings are unchanged.
- Preserve keyset pagination correctness: excluded private rows do not create duplicates, cursor leakage, or missing ordinary neighbors.
- Add a narrow atomic direct bookmark operation keyed by `(messageId, attachmentId, owner_lane='direct')` and guarded by the current parent remaining live, visible, ordinary, and non-private. Return a typed/boolean race loss; do not throw after a legitimate current-state denial.
- Use that guarded operation from `DirectMediaLibraryController`. A loaded ordinary row that becomes private before bookmark dispatch gets zero mutation and is removed/refreshed truthfully. Do not change the generic group/announcement bookmark contract.
- Batch Save/Share uses the central current-row decision per identity. Delete-for-me remains allowed through its current durable parent re-read/tombstone path and is not converted into egress.
