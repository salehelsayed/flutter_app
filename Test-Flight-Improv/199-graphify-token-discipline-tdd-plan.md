## Exact Problem Statement

This repo runs a two-graph graphify setup (`graphify-arch/` default, `graphify-out/` fallback) enforced by a blocking Bash grep-gate hook, a non-blocking Read/Glob nudge hook, a `graphify-explorer` subagent, and graphify-first framing in `CLAUDE.md` and `.claude/skills/tdd-plan/SKILL.md`. A token-usage audit (workflow `wf_02c2e3c6-ea2`, 5 parallel agents, 188,546 tokens) plus a round-2 adversarial verification (workflow `wf_c1876316-b3f`, 5 agents, 242,097 tokens) found this machinery is inconsistently applied, enforced only by prose, and has several unguarded raw-dump vectors:

1. **`.claude/skills/spec-doc/SKILL.md` Step 2** (the evidence-gathering `Explore` agent, lines 23-58) has zero graphify integration — it dispatches a single "very thorough" Explore agent that raw-sweeps `lib/`, `go-mknoon/`, `go-relay-server/`, `test/`, `integration_test/`, `Test-Flight-Improv/` with no graph query anywhere, unlike `tdd-plan/SKILL.md` Step 1 which is explicitly graphify-first. Since `/spec-doc` runs before `/tdd-plan` in the authoring chain, this is the one step that pays full raw-sweep cost every time, first. **This is the highest-value token item in this plan.**
2. **No reusable "scout once, fan out many" pattern** exists in `.claude/workflows/`. Each exploration-flavored `agent()` call re-runs its own `graphify query` from scratch even when several agents in a phase need overlapping context — measured in the original audit at ~37.7K tokens/agent average for what was substantially one shared context. Separately, `.claude/agents/graphify-explorer.md:34-35` phrases `--budget 1500` as an example ("Add `--budget 1500` to cap output") rather than a mandatory instruction — and no mechanism anywhere *enforces* budgeting (see item 6). Measured on a live arch-graph query this session: budgeted output 4,660 B (~1,165 tok) vs uncapped 6,166 B (~1,542 tok) — the cap's value is bounding the worst case on broad questions, not the average case.
3. **Raw-dump guard gaps around graph artifacts — severity corrected, gap list expanded.** Sizes: full `graphify-out/graph.json` = 115,798,170 B; arch copy = 40,206,553 B (and the arch copy is *git-tracked*). Severity: official docs confirm the harness caps Bash output at 30,000 chars (file-spool beyond; `BASH_MAX_OUTPUT_LENGTH` ceiling 150K) and Read returns a token-capped `PARTIAL view` page — so a raw dump is an **~8-25K-token accident per occurrence, not a 110MB catastrophe**; this guard is cheap steering/defense-in-depth, not catastrophic-loss prevention. Mechanism correction: the existing Read/Glob nudge matches its extension tuple by **substring** (`any(e in s ...)` — `'.js'` is contained in every `.json` path), so `.json` files DO nudge today; `graph.json` specifically gets no nudge only because of a separate `'graphify-out/' not in s and 'graphify-arch' not in s` exclusion clause. Gaps found in round 2 that the original design missed: (a) ~20 dated backup copies at `graphify-out/YYYY-MM-DD/graph.json` evade both the proposed `graphify-out[/\\]graph\.json` regex and the `Read(**/graphify-out/graph.json)` glob (the parent dir is the date, not `graphify-out`); (b) the script's `GRAPH_OK` early-return fires *before* any other check, so `GRAPH_OK=1 cat graphify-out/graph.json` would unlock the new dump gate unless the bypass is re-scoped; (c) `jq . graph.json` (the single most realistic agent move on a JSON file), `head -c`/`tail` with explicit counts, `awk`/`sed`, and `git show|diff` naming the tracked arch copy are all uncaught by a `cat|less|more|bat` deny-list; (d) **GRAPH_REPORT.md — full ~1,134,007 B (~283.5K tok), arch ~244,960 B (~61.2K tok) — has no guard at all**, and unlike a 110MB JSON blob it is an artifact an agent plausibly *chooses* to read wholesale.
4. **`graphify-out/cost.json` (full graph only) is blind.** It logs two runs (2026-06-06, 2026-06-11), both showing `"input_tokens": 0, "output_tokens": 0`, and nothing since — despite 27 dated `graphify-out/YYYY-MM-DD` backup folders (21 post-dating 06-11, through 2026-07-03) proving the graph kept getting rebuilt. Two compounding mechanisms: (a) the cost-append logic lives in `.claude/skills/graphify/SKILL.md`'s own bash block, which only runs in the full `/graphify` skill flow — `CLAUDE.md:14`'s recommended bare-CLI `graphify update .` never reaches it; (b) even in the full flow, `SKILL.md:275` requires a manual token-backfill from Agent-tool `usage` fields — a single unenforced prose sentence, evidently skipped on both logged runs. **Expectation reframe (round 2): fixing this is bookkeeping honesty with ZERO session-token savings** — cost.json structurally measures only graph-*build* spend, which is ~0 under this repo's usage pattern; actual token spend is session-side (sweeps, fan-outs — the audit itself cost 188.5K, the round-2 verification 242.1K), and session-side observability is explicitly out of scope here.
5. **No canonical multi-stage `pipeline()` template exists in `.claude/workflows/` — premise corrected.** Confirmed: zero `pipeline(` across the 14 scripts in the original glob (`.claude/workflows/one-to-one-media-unavailable-debug.js` + 13 `.claude/wf-124-*.mjs`). But "all use `parallel()` exclusively" was wrong: `wf-124-phase3.mjs` is purely sequential (zero `parallel(` too); `.claude/wf-harness-audit.mjs` is a 15th loose workflow the glob missed; and three hidden scripts at `Test-Flight-Improv/Move-Feature/.move-*-workflow.js` **already use `pipeline(`** (1, 2, and 1 occurrences). The real gap is a *canonical, discoverable* template in `.claude/workflows/`, not absence of precedent. This remains a wall-clock concern, not a token concern.
6. **NEW (round 2) — no mechanical enforcement of any token-discipline rule.** Budgeting and graphify-first live entirely in prose (skill/agent docs) — the weakest enforcement layer this repo has — while the repo already proves mechanical enforcement works (the blocking grep gate). An unbudgeted `graphify query` is never stopped, and every documented query example (root `CLAUDE.md` rules bullet and arch-graph bullet, `tdd-plan/SKILL.md:57`, `graphify/SKILL.md`'s "Project graph selection" bullets) is itself unbudgeted — the docs teach the undisciplined form.
7. **NEW (round 2) — templates that aren't wired don't get used, and neither template spec included effort tiering.** Nothing in `tdd-plan/SKILL.md` or `spec-doc/SKILL.md` (the flows that actually spawn fan-outs) would reference the new templates; and the Workflow tool's `opts.effort` (`'low'` for mechanical stages) is a direct spend lever the original plan never mentioned.

What must improve: spec-doc grounds itself in the graph before sweeping; unbudgeted `graphify query` is mechanically denied (hook), and every documented query example carries `--budget`; both graph.json copies AND their ~20 dated backups cannot be raw-dumped via `Read` or via a widened dump-tool list in Bash (including `jq`, explicit-count `head`/`tail`, `awk`/`sed`, and `git show|diff`), and `GRAPH_OK` cannot unlock that gate; GRAPH_REPORT.md reads get a steering nudge (advisory, not deny); the scout-then-fan-out and pipeline templates exist, demonstrate `effort:` tiering, and are referenced from the skills that spawn fan-outs; the token-backfill step feeding cost.json is impossible to silently skip and a future $0 entry is loudly flagged; cost.json's actual coverage (full-skill-flow-only) is documented.
What must stay unchanged (→ preserved-green sentinels): the existing Bash grep-gate denial behavior; `GRAPH_OK` still bypassing the **grep** gate (scoped — it must NOT bypass the new dump gate); the existing Read/Glob advisory nudge **including its substring-match behavior** (`.json` paths like `package.json` keep nudging — consciously preserved, no silent behavior change during the port); ordinary `Read`/`Glob` calls on non-graph files; `graphify path`/`graphify explain` staying un-gated (budget gate is scoped to the `query` subcommand); the "## Project graph selection (this repo)" section of `.claude/skills/graphify/SKILL.md` (its bullets gain `--budget` flags but the section and its DEFAULT/FALLBACK guidance survive); the existing rules already documented in root `CLAUDE.md`.
