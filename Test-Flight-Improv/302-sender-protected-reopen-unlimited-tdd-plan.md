## Problem And Evidence
- Behavior to improve: the sender of a 1:1 "Protected view" photo gets exactly ONE post-send re-open. Closing the viewer terminalizes the sender's copy: the bubble becomes the terminal card ("Private media" + "You've used your one more look") and the sender's local bytes are wiped. The receiver, by design, re-opens without limit. Product decision now: the sender must match the receiver — unlimited in-app re-opens for protected mode; the view-once budget is untouched everywhere.
- Impact: senders lose their own protected photos after one look while the recipient keeps viewing them — inverted ownership semantics; with plan-301 thumbnails in the working tree the collapse is now visually loud (thumbnail → terminal card).
- Confirmed current mechanism (survived the adversarial refute pass; every hop verified in current source):
  1. Open: outgoing bubble/tile tap → `_openPrivateMediaFromConversation` → `DirectPrivateMediaViewerController._prepareResult`; `_requiresOpeningLease` returns true for `outgoing: protected || viewOnce` (`lib/features/conversation/application/direct_private_media_viewer_controller.dart:1002-1010`) → `openOneShot` claims the one-shot lease (`lib/core/media/private_media_lifecycle_engine.dart:248-293`; its doc `:246-247` names "the sender-only one-more-look contract"); adapter `claimOpening` CAS moves the row `available → opening` (`lib/core/database/helpers/messages_db_helpers.dart:1983-2011`).
  2. Close: viewer back → `settle` → `_settleGrant` — first frame recorded ⇒ intent `terminalize` (`direct_private_media_viewer_controller.dart:714-752`) → `consumeOpening` (`lib/features/conversation/application/direct_private_media_lifecycle.dart:826-836`) writes state `consumed` (terminal) and the same settlement runs terminal cleanup: `_deleteExactAppOwnedArtifacts` unlinks canonical + pending + thumbnail + `.part`/`.enc` siblings, deletes the encryption key fail-hard, deletes the attachment row (`direct_private_media_lifecycle.dart:1125-1199, 983-1002`).
  3. Render: `conversation_screen.dart:534` (terminal ⇒ null identity) + `:1062-1091` → `DirectPrivateMediaTerminalPlaceholder(direction: outgoing, state: consumed)` → title `private_media_notification_body` ("Private media") + body `private_media_sender_consumed` ("You've used your one more look") (`lib/features/conversation/presentation/screens/direct_private_media_viewer.dart:362-409`). Exact screenshot match.
  4. Receiver asymmetry: incoming protected requires no lease (`:1004-1005`), settles `noLease` with zero adapter calls (`:722-724`) — unlimited re-opens. This is the template the fix extends to outgoing protected.
- SQL writer census (refuter, complete): the only writers that move an outgoing protected row out of `available` are the lease claim (`dbClaimDirectPrivateMediaOpening`, requires `state='available'`) and the quarantine inside lease settlement; `dbConsumeDirectPrivateMedia` requires `state IN ('opening','viewing')` (`messages_db_helpers.dart:2159`). Every terminalization is downstream of a prior lease claim ⇒ removing the claim removes the latch. Expiry sweeps are incoming-disappearing-only (`:2177-2196, 2395-2401`); delete/contact wipes are user-initiated, not open/close.
- The budget is designed, shipped behavior: both predicates byte-identical at committed HEAD (`git show HEAD:` verified); composer copy promises "You can reopen it once here after sending." (`app_en.arb:1805`); index section 3I ("Sender protected-media one-more-look independence", plan 262) built sender-open authority around this contract. Plan 302 deliberately supersedes the protected half of that contract; view-once keeps it.
- Existing coverage: the old contract is pinned by ~27 test cases across 10 files (blast-radius inventory in Test Contract / Scope); the exact reported bug exists as a PASSING test today (`test/features/conversation/application/direct_private_media_sender_pending_open_test.dart:233-272`: protected first-frame → `viewing` → close → `consumed`).
- Missing coverage (causal gaps this plan closes): no test asserts an outgoing-protected open grants WITHOUT a lease, survives repeated open/close cycles with state `available` and bytes intact, or that upload completion commits immediately (not deferred) under an open lease-free protected viewer.
