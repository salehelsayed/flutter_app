## 7. Cloud & Compute

**Grade:** C · **Status:** Partial · **Decentralization:** heavy compute correctly on-device; one centralized relay box carries the rest

**Assessment.** The compute architecture is genuinely good: all expensive work — post-quantum ML-KEM E2E crypto and libp2p routing — runs on the embedded `go-mknoon` node on the client, so there is no app-server fleet to scale and no centralized plaintext. The flip side is that every centralized function (offline message queue, peer rendezvous/discovery, NAT-traversal relay circuits, media blobs, FCM push) is concentrated on a *single* EC2 relay box in a single region/AZ, deployed by hand via systemd, defaulting to an in-memory backend, with no standby, no IaC, and recovery that is human-paced. The resilience machinery exists and is mostly *enabled* — a Redis backend, two-instance failover (proven by tests), multi-relay routing turned ON by default, portable relay identity, monitoring — but none of the redundancy is actually *deployed*: there is exactly one relay host and one (co-located) backend, so the failover code has nothing to fail over to. It is a deliberate pre-launch cost posture, not a hardened one.

**What exists (and how good)**
- On-device heavy compute (ML-KEM E2E, libp2p routing in embedded `go-mknoon`) — strong; removes any need for a compute fleet — `lib/core/bridge/p2p_bridge_client.dart`, `go-mknoon/node/node.go`
- Thin store-and-forward relay (inbox/group-inbox, rendezvous, relay-circuit, media, push) bounded by finite limits (512 reservations, 8 circuits/peer) — adequate, prevents single-box resource exhaustion — `limits.go:40-47`, `main.go:62-79`
- Redis backend + proven 2-instance shared-state failover (cross-instance and cross-process tests pass) — strong code, **not deployed** (one box, one backend) — `backend_redis.go:41-47`, `failover_test.go:51,100`, `redis_failover_integration_test.go:44`
- Multi-relay routing **enabled by default** (Go `EnableMultiRelayRouting: true` and Flutter `defaultValue: true`); truncation to one address only happens if the flag is *off*, which is not the default — strong, but inert until a 2nd relay address exists — `go-mknoon/node/feature_flags.go:34-44`, `lib/core/bridge/p2p_bridge_client.dart:37-40`, `feature_flags_runtime.go:20-30`
- DNS-addressed relay + env-overridable Ed25519 identity → portable peer ID for a replacement box (cheap manual failover lever) — adequate — `server_config.go:84-93` (`RELAY_PRIVATE_KEY`), `go-mknoon/node/config.go:11,15`
- Graceful Firebase degradation + push retry/invalid-token cleanup + >4K media fallback — strong — `inbox.go:92-107,180-216,295-308`
- Observability: Prometheus `/metrics` on `:2112`, per-60s heap/goroutine/disk stats, node_exporter, 4 Grafana dashboards (relay/host/redis/business) — adequate, but the whole stack is co-located on the one box (`localhost` scrape targets), so it dies with the host it watches — `main.go:204-211,240-298`, `NOTES.md`, `grafana-*-dashboard.json`

**Gaps / what is missing**
- **[high]** Single relay instance is a SPOF on the critical path (offline delivery, discovery, NAT relay, media, push); only fully bypassed when both peers are simultaneously online and mutually reachable — `server_config.go:57-67`, `go-mknoon/node/config.go:11,15`, `network_constants.dart:13-14`
- **[high]** No region/AZ redundancy, no LB, no autoscale, no standby; recovery is manual with no IaC (no Terraform/Docker/CI) — only systemd `Restart=on-failure` / `RestartSec=5` (process-crash only, not box/AZ/disk/hang) — `README.md`
- **[critical]** Durability unconfirmed: backend defaults to `memory`, where a restart wipes the entire offline queue + rendezvous + push tokens; Redis is opt-in and *requires* `REDIS_URL`. Prod presumably runs Redis (incident logs cite the `relay:` prefix), but Redis persistence (AOF/RDB) and hosting (managed vs co-located) are not in the repo — `server_bootstrap.go:35-54,88-91`
- **[medium]** Media (5GB/blob, 5GB/peer pending, 7d TTL) lives under `/data/media` on the box's EBS volume, and Redis (if co-located) shares it → disk-full / single-volume-loss risk, no S3 offload — `media.go:21,23,27-28`
- **[medium]** Failover/horizontal scaling is built and *enabled* but inert: only one relay host is deployed and the client's two default addresses are two transports (WSS + QUIC) to the *same* `mknoun.xyz` box — there is no second relay to route to. (Correcting the earlier read that the flag was OFF — it is ON.) — `go-mknoon/node/config.go:11,15`, `lib/core/bridge/p2p_bridge_client.dart:28`, `feature_flags.go:34-44`
- **[low]** No dedicated liveness/health endpoint and no *external* probe — `/metrics:2112` is scraped by Prometheus running on the same box, so a hung-but-running process (or a dead box) is neither auto-restarted nor externally alerted — `main.go:204-211`, `NOTES.md`
- **[low]** Single Firebase project, no secondary push channel; no documented instance-sizing/headroom target

**Decentralization note.** N/A by design: an app-server fleet, load balancer, and compute autoscaling — the crypto/routing tier is fully on-device, which is the right call. Genuinely owed (not N/A): the relay box is real centralized compute on the critical path for offline delivery and discovery, so it owes durability (persistent Redis) and at least one redundant instance — both of which the codebase is already architected and flag-enabled for, but has not deployed.

**Recommendations**
- **Now:** Confirm/lock prod to `RELAY_BACKEND=redis` + `REDIS_URL` with AOF persistence and document it; add an *external* uptime + liveness alert (off-box); write a one-page recovery runbook (provision EC2 → install binary → set `RELAY_PRIVATE_KEY` → repoint `mknoun.xyz`) (S)
- **Next:** Stand up a 2nd relay in another AZ sharing one off-box Redis (e.g. ElastiCache Multi-AZ), then add that relay's address to client `RelayAddresses` / `MKNOON_RELAY_ADDRESSES` — the `EnableMultiRelayRouting` flag is already on, so no flag flip is needed; offload media to S3 and move monitoring off the relay box (M)
- **Later:** Codify relay + Redis + DNS as Terraform for repeatable multi-AZ provisioning; add standby/autoscaling for the relay tier and a fallback push path for FCM-blocked regions (L)
