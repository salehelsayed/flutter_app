03 · Offline delivery

One promise for text and media.

Text already saves first, retries automatically, and tells the user “Will send when you’re back online”. That stays exactly as it is today. Media saves a durable local copy too, yet the same temporary network problem is presented as a red failure with manual Retry. The proposal gives queued media the promise text already makes.

Production behavior proposal

Make the durable outbox the source of truth.

Do not infer terminal failure from the parent message’s failed status alone. Project one visible state from the parent plus every attachment, and let a single idempotent worker own both automatic and user-triggered recovery.

1Save before networkCommit the message, protection mode, durable file path, and stable blob ID before upload.
2Wake media on reconnectWake the media coordinator from the fast network-restored path; keep node-online, resume, and periodic retries as backstops.
3Keep one operationClaim work with a durable lease/CAS. Foreground, reconnect, resume, and manual actions reuse the same message and blob IDs.
4Separate transient from terminalupload_pending means automatic. Only upload_failed or a missing local copy exposes manual recovery.
5Return typed outcomesOffline/no route stays queued and does not consume the terminal retry budget. Missing files and invalid input stop with a precise reason.
6Promote before cleanupPersist and verify the canonical media path before deleting the pending-upload directory, so a recovered photo still renders for its sender.

Bind feedback to its object

A failed message, invite, setting, or media item should carry its own state.

Match the lifetime

Persistent truth stays visible. A two-second toast cannot explain a blocked screen.

Expose the right recovery

Say “No action needed” while automatic retry owns the item. Show a button only when the user can meaningfully help.

Reserve red for failure

Success, progress, warning, and destructive actions need distinct semantic treatments.

06 · Copy revision

Same design, fewer words.

A second pass over every string a user would actually see in the mockups above. The phone screens now use the revised copy by default; flip the Original / Revised toggle in the header to compare. In Original view, changed strings show a dotted underline. Each change and its reason is below, so you can accept or reject per row.

REMOVE LEAKED ANNOTATIONS

Design notes are sitting in user-visible slots

“This is a terminal local-file problem—not an offline wait.”, “Download progress stays here.”, “Tap once—not twice”, and “The composer is replaced while this state is true.” are notes to reviewers placed where app copy belongs. The captions under each phone already carry that rationale.

ONE FAMILIAR PROMISE

Media borrows the words text already uses

Offline text keeps today’s “Will send when you’re back online” snackbar untouched. Queued media shows the same sentence with the offline icon on the bubble. One promise learned once, with no new “Waiting for connection” vocabulary.

CUT TITLE + BODY ECHOES

Bodies that restate their titles

“Invite expired / This invite can no longer be used.”, “Allow microphone access / Mknoon needs microphone access…”, and the sheet title plus its subtitle each say one thing twice. A body line earns its space only by adding new information.

TRUST THE ABSENCE OF CONTROLS

Don’t narrate what the UI already shows

“No action needed.” warns against a button that isn’t on screen, and “Sent to inbox” invents a place this app doesn’t have. A progress bar and a plain “Sent” carry the same meaning with zero extra words.
