## Problem And Evidence
- Behavior to improve: (A) after **every** Android call (clean hang-up included) the app can neither place ("Couldn't start voice call") nor present an incoming call (caller sees `permissionDenied`) until it is force-stopped; (B) on iOS one failed capability re-advertisement (observed `call_token_set_v1 → CALL_STALE_EPOCH` on resume) revokes the endpoint + VoIP token and ends the live CallKit call, and the token coordinator then stays latched invalid until process restart; (C) dev-signed iOS builds label a sandbox PushKit token `production`, so every wake first costs a rejected APNs attempt (relay now falls back); (D) the caller re-resolves the callee's directory record for every control signal, so a callee whose record vanishes mid-call makes the offer and even the hang-up fail.
- Impact: (A) makes voice calling single-use per process on Android; (B) drops answered calls and leaves the iPhone uncallable; (C) doubles APNs traffic and keeps `relay_apns_voip_push_attempts_total{outcome="invalid_token"}` climbing; (D) turns any transient directory blip into `mediaFailed` plus a stranded callee.

## Scope Contract And Guard
In scope:
- A. Android: a system-default route reset against a handle whose native call already ended is a successful no-op; route-reset failure at cleanup is best-effort (never `cleanupFailed` by itself); `_closeCallMediaBundle` names its failing stage in `CALL_MEDIA_CLOSE_FAILURE_STAGE`.
- B. iOS: advertisement failure while `coordinator.activeSession` is non-terminal defers (returns false, revokes nothing, no native `failClosed`) and is retried once when that session reaches a terminal snapshot; a terminal-but-still-present session counts as idle; idle advertisement failure revokes the endpoint only (VoIP token kept; full rollback stays for graph close). Token-authority invalidation (`authorityInvalidations`) during a live call is deferred the same way at BOTH sites — the composition listener (`call_signaling_composition.dart:650-655`) and the graph's `_handleIosTokenInvalidation` (`production_call_signaling_graph.dart:841-850`) — and applied at terminal; native-lifecycle invalidation stays immediate (the native call is already dead). `_reconcileContactEligibility` defers while a live foreground call exists. `IosVoipTokenCoordinator`: a relay rejection (`authorityFailure`) publishes one invalidation, does NOT revoke the token (the relay already refused it; a CAS revoke here is what poisons the epoch high-water) and does not latch `_invalid`; native failure keeps today's latch + CAS revoke.
- C. iOS: `EntitlementVoipEnvironmentProvider` prefers the signed `aps-environment` from the embedded provisioning profile and falls back to Info.plist (App Store builds carry no embedded profile → `production`).
- D. Both signaling adapters pin the resolved endpoint per call in `CallSignalingContextStore` (first successful resolution for that call, caller or callee side; the store is already purged by the `call_signaling_context` cleanup step). `send` (control) and `_transmit` (negotiation) use the pin ONLY when resolution fails with `CallEndpointResolutionCode.unavailable` (record absent) or a transient `CallAuthorityErrorCode.bridgeFailure`, the pinned device equals the signal's recipient device, and the pin's `expiresAtMs` is in the future. The `invite` signal never uses the pin (a fresh directory record is the callee's consent to be woken; relay `Store` wakes by token route without checking the endpoint, `go-relay-server/call_control.go:309-311`). `blocked` / `notAccepted` / `stale` / `mismatched` / `unlinked` / `invalidSignature` / `ambiguous` always fail closed, pin or not.
