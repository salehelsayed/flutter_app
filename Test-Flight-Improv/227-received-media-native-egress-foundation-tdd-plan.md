## Problem And Evidence

- Behavior to improve: a user who has received completed images/videos must be able to save one or a bounded selection to Photos/Gallery or Files/Downloads, or hand one selection to the OS chooser.
- Impact: the only current action is in-app viewing; users cannot retain or reuse ordinary received media outside Mknoon.
- Confirmed current gap: `FullScreenImageViewer` accepts only `localPath`, `allPaths`, and an optional video builder at `lib/shared/widgets/media/full_screen_image_viewer.dart:19`; its app bar has only Back and a page counter at `:62`.
- Confirmed current mechanism: `MediaFileManager.resolveStoredPath` re-roots recognized relative/stale paths at `lib/core/media/media_file_manager.dart:219-258`, but intentionally returns unknown absolute paths unchanged; `test/core/media/media_file_manager_test.dart:309-313` locks that pass-through. Resolution is therefore required before egress but is not proof of app ownership.
- Confirmed current gap: `ShareIntentService` wraps only `receive_sharing_intent` at `lib/core/services/share_intent_service.dart:16`; `pubspec.yaml:63` has an inbound share dependency but no outbound media egress implementation.
- Confirmed platform gap: Android has inbound `ACTION_SEND`/`ACTION_SEND_MULTIPLE` filters at `android/app/src/main/AndroidManifest.xml:43-84` but no outbound FileProvider/MediaStore handler in the manifest or `MainActivity.configureFlutterEngine` (`android/app/src/main/kotlin/com/mknoon/app/MainActivity.kt:15-81`). iOS has read-library usage copy at `ios/Runner/Info.plist:58-59` but no add-only usage key or egress channel among the implicit-engine registrations at `ios/Runner/AppDelegate.swift:185-198`.
- Existing coverage: `test/core/media/media_file_manager_test.dart` covers path resolution and app-owned deletion guards, not egress ownership containment; `test/core/services/share_intent_service_test.dart` covers inbound buffering. Neither can fail for outbound Save/Share behavior.
- Missing coverage: no Dart decision/gateway test, canonical ownership-escape test, native Kotlin/Swift contract test, version-specific Android proof, deterministic single/batch OS proof, permission reset proof, concurrent-presentation proof, or native partial-output rollback proof exists.
- Refuted findings: “received media is not downloaded” is refuted — completed attachments live under app Documents and are displayable; the missing behavior is user-visible egress, not relay download.
- Unresolved findings: N/A after revision — Android share returns truthful `presented` rather than an unobservable cancel/delivery result; lane adapters own current-message policy qualification; version and permission branches have explicit proof legs.
- Affected production, test, and gate files: new Dart egress contract/gateway, an app-owned-path validator, isolated Android/iOS egress handlers/coordinators plus registration edits, least-privilege manifest/plist/FileProvider configuration, Dart/native/device tests, deterministic fixtures, a separately packaged Android URI-reader proof receiver with installer script, and device-proof discovery.

## Scope Contract And Guard

In scope:
- Add public finite `kMaxMediaEgressItems` plus bounded-list `MediaEgressRequest`, `MediaEgressItem`, `MediaEgressDestination`, `MediaEgressItemResult`, aggregate `MediaEgressResult`, `ReceivedMediaEgressGateway`, and `ReceivedMediaEgressService`. The contract is bounded by the constant; lane plans do not invent separate native limits.
- Keep policy and structural authority separate. Plans 231/233/235/237/239/241 and later policy plans must reload the current durable lane row and qualify received/incoming, completion, integrity, expiry, view-once, and protection state before constructing an egress item. Plan 227 does not infer those feature-specific facts from caller-supplied booleans; it owns cap, identity conflict, supported MIME, file existence, and canonical app-owned-path enforcement.
- Resolve each stored path, normalize it, resolve symlinks/real paths, and require separator-aware containment within the current Documents directory's `media/`, `local_media/`, or `post_media/` roots. `pending_uploads/`, arbitrary absolute paths, traversal, prefix-confusion, symlink escape, missing files, unsupported MIME, and duplicate IDs whose path/MIME/name metadata conflict are rejected. Deduplicate identical IDs stably and preserve first-selection order. Save may send the ordered valid subset and return per-item partial truth. Because Share intentionally has no item results, any structural rejection makes the whole Share request aggregate `rejected` with zero native call; Share never silently presents a partial selection.
- Freeze one channel: `mknoon/received_media_egress`, method `perform`, arguments `{requestId, destination, items}` where destination is `photos|files|share` and every item is exactly `{attachmentId, sourcePath, mime, displayName}`. `requestId` must match `^[A-Za-z0-9_-]{1,64}$`; separators, control characters, whitespace, Unicode lookalikes, and longer values are rejected before native work. `displayName` is a sanitized stable attachment/blob identifier plus MIME-derived extension, never caption or user text. Reject unknown keys/types, blank IDs, oversized lists, malformed MIME, hostile request IDs, or duplicate conflicts before native work.
- Freeze the native result envelope `{requestId, outcome, items}` and each item as exactly `{attachmentId, outcome}` with no details/message/path field. Save item outcomes are `saved|cancelled|busy|permissionDenied|missingFile|unsupportedType|outsideOwnedRoot|identityConflict|platformFailure`. A native Save response contains exactly one item for every native input, in the same order and with no duplicate/unknown ID; the Dart service merges structural and native items into exactly one final item per first-seen stable ID in original selection order. Share responses always contain `items: []`.
- Freeze aggregate precedence. `busy` wins when no operation starts; `cancelled` applies only to a cancelled Files picker; `saved` requires every final Save item to be saved; `partial` requires at least one saved and one non-saved item; with no saved item, `platformFailure` wins over `permissionDenied`, which wins over `rejected`; `rejected` means only structural item failures remain. Share returns `rejected` with zero native call when any selected item fails structural validation; an all-valid Share returns only `presented|busy|platformFailure`. For Save, a mismatched request ID, missing/extra/reordered native item, unknown outcome, or malformed result maps the aggregate and every native-eligible item to redacted `platformFailure` before merging any structural items; for Share it maps to aggregate `platformFailure` with `items: []`. Neither case may retain partial native success.
- Freeze channel error behavior. Unknown native method -> `FlutterMethodNotImplemented`; malformed `perform` arguments -> `FlutterError(code: "invalid_arguments", message: "invalid request", details: null)`; well-formed calls return only the frozen envelope. Dart-side cap/identity/path/MIME rejections do not invoke the channel. No native error/result echoes input, `sourcePath`, external destination path, exception message, or granted URI.
- Android API 29+: save Photos through the appropriate Images/Video MediaStore collection and Files through `MediaStore.Downloads`, using `RELATIVE_PATH` and `IS_PENDING`; publish only after a complete copy and delete only the invocation-owned pending row on failure. Android API 24-28: use public Pictures/Movies/Downloads with a unique request-and-item staging name `.mknoon-egress-<safeRequestId>-<zeroBasedNativeItemIndex>.part` plus atomic rename/media scan, never overwrite an existing output, and request legacy storage permission only on this branch. Cap both existing `READ_EXTERNAL_STORAGE` and new `WRITE_EXTERNAL_STORAGE` declarations with `android:maxSdkVersion="28"`; API 29+ must request neither.
- Treat save staging as managed durable state. Pending MediaStore rows and legacy `.part` files use the same exact filename-safe request-and-item marker grammar and never the final name until commit, so two images in the same directory cannot collide. On native-handler initialization after process start, before accepting a Save, sweep every leftover file/owned pending row whose display name matches `^\.mknoon-egress-[A-Za-z0-9_-]{1,64}-[0-9]+\.part$` under the approved Mknoon output directories; preserve published rows, successful files, foreign/unmarked partials, and all source media. No sweep runs while a live single-flight operation exists. Caught failures still clean synchronously; startup sweep is the crash/restart fallback.
- Android Share: expose the existing validated app-owned originals through non-exported, grant-enabled FileProvider roots limited to approved media subdirectories; construct `ACTION_SEND` for one item and `ACTION_SEND_MULTIPLE` for a batch, ordered `content://` `EXTRA_STREAM` plus `ClipData`, `FLAG_GRANT_READ_URI_PERMISSION`, and no write grant. Mixed image/video batches use a truthful common/wildcard intent MIME while retaining each MIME in channel metadata. Return `presented` immediately after successful chooser launch; do not wait for a cancellation callback.
- iOS Photos: use `PHPhotoLibrary.performChanges`; on iOS 14+ request `.addOnly`, while iOS 13 attempts the add operation under `NSPhotoLibraryAddUsageDescription` without expanding egress to read-library access and maps authorization errors truthfully. iOS Files: use `UIDocumentPickerViewController(forExporting:asCopy: true)` on iOS 14+ and the iOS 13 multi-URL `.exportToService` initializer fallback. iOS Share uses ordered URLs in `UIActivityViewController` and returns `presented` after successful presentation.
- Register isolated native handlers from `MainActivity.configureFlutterEngine` and `AppDelegate.didInitializeImplicitFlutterEngine`; native egress logic does not live inside transport-owning activity/delegate files. Present UIKit controllers on the main thread from the foreground-active scene's topmost controller, configure the iPad popover anchor, retain picker/coordinator delegates until dismissal, and fail terminally when no presenter exists.
- Allow one interactive native operation at a time. A second request returns typed `busy` without presenting. Native completion latches ignore duplicate/late callbacks. Android keeps the interaction busy until the chooser pause/resume cycle completes even though Dart already received `presented`; iOS clears it on controller dismissal.
- Create no Share temporary copies in this plan. Photos/Files use only the explicitly managed commit staging above and Share reads the validated stable original. If Share staging or any other durable cache is discovered, stop and revise the plan with separate request-scoped lease/restart semantics before adding it.

Must preserve:
- Relative/stale path recovery -> `test/core/media/media_file_manager_test.dart`; `GREEN sentinel`.
- Inbound cold/warm share capture -> `test/core/services/share_intent_service_test.dart`; `GREEN sentinel`.
- Android inbound share filters/single-task behavior survive while both legacy storage permissions become API-28-capped and FileProvider remains non-exported/read-only -> existing `test/core/services/share_intent_android_test.dart` updated as TC-227-12.
- App-private originals remain byte-identical after every save/share/cancel/failure -> `received_media_egress_service_test.dart::egress never deletes or rewrites the source attachment`; causal preservation row.
- Foundation sources import no database helper/repository and cannot update attachment/message rows -> `received_media_egress_transport_boundary_test.dart`; downstream lane tests retain real-row preservation ownership.

Hard `Do not`:
- Do not call `P2PService`, Bridge, relay, inbox, group publish, or go-libp2p code.
- Do not grant a raw filesystem path or broad storage permission to another app.
- Do not let any user-facing lane export pending, missing, integrity-failed, view-once, disappearing-expired, or policy-protected media. Lane adapters enforce current durable policy; this foundation independently enforces path/MIME/file safety and forbids direct gateway use by UI callers.
- Do not claim that deleting a Mknoon message revokes a copy already saved/shared outside the app.
- Do not configure FileProvider with `root-path`, broad external roots, or write grants; do not delete arbitrary absolute/gallery paths or another request's native output during rollback.
- Do not add unmanaged durable temp/cache state or sweep unmarked/foreign/successful output.

Deferred / accepted difference:
- Viewer/bubble buttons and lane policy are owned by plans 231, 235, and 239.
- Library selection and UX are owned by plans 233, 237, and 241; this foundation proves both one-item and bounded-list native egress so those host plans do not make an unclosed batch-platform claim.
- Android API 24-28 and API 29+ are separate implementation branches. Legacy permission UX may use the existing `permission_handler` or an isolated native coordinator, but its accept/deny behavior and capped manifest permission must be causal-tested natively. Under the repository Mobile Target Availability Policy, a live API 24-28 device leg runs only if such a USB device/emulator is already available; its absence is N/A and non-blocking. API 29+ must not request legacy storage permission.

Dependencies:
- Existing `MediaFileManager` path-resolution rules, a new canonical app-owned containment validator, app lifecycle/active-scene availability, Android minimum API 24, and iOS minimum 13.
- No dependency on 1:1, group, or announcement delivery plans.

- Permission allow and deny are separate runs. Each permission-sensitive run asserts native status is `notDetermined` first and fails with reset/reinstall instructions otherwise. Cancel/deny creates no external output; test-created outputs use run-unique names and have documented manual cleanup.
- Diagnostics may include request IDs, attachment-ID prefixes, API band, and typed outcomes, never source paths, captions, user-derived filenames, granted URIs, media bytes, or external destination paths.
