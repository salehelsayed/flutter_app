=== the false trail, worth remembering ===
The first look showed nothing, and the capture had NO LOAD_ORBIT_DATA_START.
Concluding "Orbit was never opened" from that absence would have been unsound:
the check that made it meaningful was a LAYER CENSUS of the capture —
FL 956, DB 238, GO 4, CALL_SIGNALING_COMPOSITION 2, and **zero UC**. Since
`flow_event_emitter.dart` does no layer filtering, UC silence proved the code
had genuinely not run rather than that logging was off.

Cause: `loadOrbitData` runs when OrbitWired MOUNTS. The screens were already
open from before the deploy, so they were still rendering data loaded by the
previous build. Restarting the app made the loader run immediately.

Rule: after deploying a change to a load-on-mount surface, a screen that was
already open proves nothing. Remount it before reading the result.

Operator note: the restart above used `am force-stop`, which this project's
notes forbid because a stopped app stops receiving FCM. Relaunching cleared it
(`stopped=false` verified), but the correct route is the HOME intent followed
by `am kill`.
