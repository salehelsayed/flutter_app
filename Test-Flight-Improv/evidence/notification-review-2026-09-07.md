## Confirmed defects and fixes

1. **Reaction wake authorization disappeared on relay restart.** Redis inboxes used an in-memory wake-token set even though direct reactions require a registered set. The relay now stores recipient-bound token digests durably, atomically replaces sets, preserves revocation, and reports storage failures instead of acknowledging unsuccessful registration. Message custody remains independent of notification authorization.
2. **Ordinary production builds did not distribute reaction wake tokens.** Token emission defaulted off while clients advertised reaction push support. Emission now defaults on with an explicit false rollback. Existing contacts receive missing tokens through the signed, encrypted contact-update path. Persistent distribution state retains failed sends, handles rotation, and prevents repeated backfill. Issuance is serialized across startup/contact bursts.
3. **Direct voice/photo/video/file notifications degraded to “Message”.** Canonical message reads do not hydrate media. Initial notification and reconciliation now load only direct-lane attachment metadata when needed. Six causal regressions failed before this change and passed afterward.

The first three fixes were preserved in commit `807874437317d6325e3de357a043aafce87a8601`. Resume review additionally declared the existing synchronized package as a direct dependency and corrected stale test-gate assertions.

4. **Queued Android direct reactions could be discarded by FCM.** They set a distinct collapse key for every reaction. More than four pending keys can cause arbitrary event loss, according to [Firebase's transport contract](https://firebase.google.com/docs/cloud-messaging/customize-messages/collapsible-message-types). Group reactions already omit this key. The direct fix preserves event identity and iOS retry deduplication while removing Android transport collapsing. The six-event serialized-payload regression failed on every event before the fix and passes afterward. This is a source/transport-contract finding, not a reproduction of the private phone's incident.

5. **iOS restored the original alert after recipient policy rejected a group push.** At 08:19:11.069832 UTC, SpringBoard explicitly logged that the extension's empty replacement would not visibly alert and that it would deliver the original content. The original sound and alert were then presented despite the extension's `sanitized` result. The current signed extension and its provisioning profile do not include Apple's [notification-filtering entitlement](https://developer.apple.com/documentation/bundleresources/entitlements/com.apple.developer.usernotifications.filtering). The sanitizer now supplies fixed, non-sensitive text with no sound, badge, provider preview, attachments, or grouping, using passive interruption on iOS 15+. The final native suite passed. On the updated physical iPhone, rejected request `4738-CEDF` at 09:02:02 UTC delivered the replacement; SpringBoard recorded `hasSound:0`, passive interruption, no screen wake, no banner destination, and no original-content restoration. The neutral Notification Center card remains by design. This prevents restoration of the original alert; it does not claim complete removal from Notification Center without that entitlement.

6. **iPhone reactions alerted again during foreground catch-up.** A controlled, single-reaction send produced remote alert `62E8-A36A` at 08:35:38 UTC, then local alert `6C23-0037` at 08:36:40 after reopening at 08:36:38. Both had OS sound-play callbacks. A preceding isolated voice control produced no local repeat. The production reaction path recognized the exact NSE shown marker but did not adopt the remote notification in the local effect ledger. Direct reactions now adopt this exact remote-presentation proof and consume it only after durable settlement. On build `260907104735`, remote reaction `4F56-D2D7` alerted at 09:00:24 UTC; reopening at 09:00:50 completed healthy catch-up without a second local notification for at least 57 seconds. Subsequent text and voice controls alerted normally and produced no local repeat after another healthy reopen.

7. **The same duplicate could return after more than 12 hours closed.** A clock-injected production-composition test advanced first reopen by 13 hours and reproduced an extra local alert; three group and logical-ID alias cases reproduced it as well. Recent-marker cleanup had deleted exact native proof before the canonical pending event could adopt it. Exact event proof now survives until its authenticated canonical owner settles or retires the event; short-lived broad conversation hints retain their existing expiry. The original failing direct counterexample and group cases pass with the fix, with matching retirement cleanup coverage. The full-host sweep, focused long-idle tests, and final-build device smoke checks completed; the 13-hour interval is tested with an injected clock, not by altering phone time.

The retention review also repaired account and alias cleanup: startup and account changes reconcile an opaque account binding before notification authority resumes; same-account restarts preserve proof, while logout or account changes remove old native and Dart records. Shared iOS gate configuration now happens before startup reconciliation, independently of deferred Firebase startup. Group alias provenance survives process interruption and is retired with its canonical event only after settlement. Cleanup failures retain retry authority; focused tests cover reset failure, restart, multiple aliases, and concurrent promotion.

8. **Android expanded reaction cards hid the current reaction behind old unread text.** Post-deployment OS payloads had the correct collapsed `android.text`, but InboxStyle `android.textLines` contained only an older unread message, matching the actual expanded screenshot. The Android renderer now reserves its final expanded line for the current reaction, retaining up to four canonical history lines within the existing five-line limit. It does not change stored history, unread counts, notification identity, visibility rules, or duplicate suppression.
