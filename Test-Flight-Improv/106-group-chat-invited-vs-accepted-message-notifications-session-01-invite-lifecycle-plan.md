## Exact Problem Statement

`pendingGroupInviteTtl` is 7 days in `pending_group_invite.dart`, and `send_group_invite_use_case.dart` uses that TTL for the invite policy expiry. `groupInviteMembershipFreshnessTtl` is 24 hours in `group_invite_payload.dart`, and `group_invite_auth.dart` builds membership freshness proofs using that shorter lifetime. Receive-time parsing/auth in `handle_incoming_group_invite_use_case.dart` and accept-time validation in `accept_pending_group_invite_use_case.dart` can therefore reject an invite as `staleMembershipFreshness` before the visible pending invite lifecycle expires.

The user-visible behavior must improve so the hidden freshness gate does not undercut a still-valid pending invite. Accepted security and expiry rejections must stay intact.
