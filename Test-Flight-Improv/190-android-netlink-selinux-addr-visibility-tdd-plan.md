## Exact Problem Statement
On every Android ≥ 11 install (targetSdk resolves to 36; restriction applies ≥ 30), SELinux denies the Go runtime's netlink route-socket **bind** (`avc: denied { bind } … tclass=netlink_route_socket`, b/155595000). Go stdlib `net.InterfaceAddrs` binds before dumping (GOROOT `syscall/netlink_linux.go:67`), so go-libp2p basichost's interface enumeration fails at construction and on every 5 s tick (`basic_host.go:46,:600-606` → `manet.InterfaceMultiaddrs` → ERROR `:396` → loopback-only fallback `:400-402`). The app's AddrsFactory (`node.go:389` → `filterAddresses` `:203-216`) then filters loopback → **`h.Addrs()` is empty**: the `Announcing 0 addresses` log (`node.go:429-434`), empty `NodeState.Addresses` (`:706-708`), empty identify snapshot (`id.go:604`), empty signed peer record for rendezvous (`basic_host.go:551-565` auto-generated; fetched at `rendezvous.go:54`), and a starved DCUtR candidate input term (`basic_host.go:271-280`). Verify→refute additionally proved the denial **also kills identify observed-address recording** (obsaddr → `Swarm.InterfaceListenAddresses` → same netlink error → `obsaddr.go:368-372` never records) — the starvation is permanent, not transient. Same-WiFi delivery survives ONLY via the FDC-11 mDNS advert lane (174), a single point of failure.

What must improve: (1) Android enumeration succeeds without the denied syscalls → real addrs flow through the **unchanged** announce/identify/record/status pipeline; (2) the 5 s ERROR spam dies **at the source** (enumeration succeeds — no log filtering); (3) the DCUtR candidate *input term* carries self-enumerated addrs; (4) a peer can dial the Android node from identify/peer-record addrs with mDNS unavailable.
What must stay unchanged (→ preserved-green sentinels): `filterAddresses` policy (loopback/link-local/unspecified dropped, `/p2p-circuit` kept), FDC-11 port-mining fallback (`node.go:1959-1967@HEAD (≈:1991 dirty-tree)`) reachable when the routable set is genuinely empty, 174's Dart advert-lane suite, iOS/macOS enumeration byte-for-byte, 189's fixtures, relay server, Kotlin lanes.

## Root Cause (verify → refute confirmed)
**Chain (all links file:line-verified; survived 5 adversarial alternatives):** stdlib `net.InterfaceAddrs` = `syscall.NetlinkRIB` = Socket+**Bind**+Sendto (`GOROOT syscall/netlink_linux.go:60-71`; bind at `:67` = the exact denied op) → `go-multiaddr@v0.14.0/net/net.go:389-403 InterfaceMultiaddrs` (raw wrapper; the module's ONLY `net.InterfaceAddrs` call — `resolve.go:73` routes through it) → three go-libp2p consumers all import manet from the go-multiaddr module path: `basic_host.go:392` (updateLocalIpAddr: ERROR `:396` + loopback fallback `:400-402`, at construction `:202` and every 5 s `:600-606`), `swarm_addr.go:56` (InterfaceListenAddresses → kills obsaddr recording `obsaddr.go:368-372`), `basic_host.go:884` (AllAddrs wildcard resolution). App `filterAddresses` (`node.go:203-216`) correctly drops the loopback fallback → 0 announced.

**Fix direction D1 (survived every attack):** `replace github.com/multiformats/go-multiaddr => ./third_party/go-multiaddr` — same-version (v0.14.0) in-repo fork, module path preserved — exactly the existing pubsub-fork pattern (`go.mod:31`; gosigar stub `:29` proves transitive-dep replaces ship through gomobile). The fork routes `InterfaceMultiaddrs` through a race-safe provider seam whose default is `wlynxg/anet.InterfaceAddrs` under `//go:build android` and stdlib under `//go:build !android`. anet@v0.0.5 avoids BOTH denied ops (no netlink bind — `netlink_android.go:56-66`; RTM_GETADDR only, never RTM_GETLINK — `interface_android.go:202,:291`; iface metadata via ioctl `:392-436`), is **already linked into the shipping .aar** (transitive via go-libp2p→webrtc→pion/ice→pion/transport stdnet, `go.mod:121`), its `//go:linkname` pulls already pass our linker (`Makefile:21-22` ships `-checklinkname=0`; grandfathered in build 1.0.0+106), and under gomobile (always cgo, GOOS=android — x/mobile `env.go:185`) its API-level autodetect works with zero injection. One seam fixes announce + status shape + identify + signed records + obsaddr recording + DCUtR input **and** kills the 5 s ERROR at the source. iOS/macOS: `!android` file = stdlib passthrough, byte-neutral.
**Companion test seam (not a behavior fix):** `replace github.com/libp2p/go-netroute => ./third_party/go-netroute` — minimal fork of v0.2.2 exposing a test-only failure hook. Needed because basichost seeds `filteredInterfaceAddrs` from netroute **before** manet (`basic_host.go:355-388`) and netroute succeeds on macOS — without blocking it, the host denial fixture false-greens. Default behavior identical on every platform (on Android it keeps failing at Debug level, gracefully — `basic_host.go:355-356`, `quicreuse/reuse.go:253` discards the error).
